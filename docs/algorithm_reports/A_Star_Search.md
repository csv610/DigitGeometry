# A* Search Algorithm

## 1. Overview
A* (pronounced "A-star") is a graph traversal and pathfinding algorithm, which is often used in many fields of computer science due to its completeness, optimality, and optimal efficiency. It is an extension of Dijkstra's algorithm that uses heuristics to guide its search, making it significantly faster in many practical scenarios.

## 2. Definitions
*   **Graph ($G$):** A set of nodes ($V$) and edges ($E$).
*   **Node ($n$):** A state or location in the search space.
*   **Cost ($g(n)$):** The actual cost of the path from the start node to node $n$.
*   **Heuristic ($h(n)$):** An estimate of the cost from node $n$ to the goal.
*   **Total Cost ($f(n)$):** The estimated total cost of the path through $n$, defined as $f(n) = g(n) + h(n)$.
*   **Open List:** A priority queue containing nodes to be explored.
*   **Closed List:** A set of nodes that have already been evaluated.

## 3. Theory
A* search balances the cost to reach a node and the estimated cost to reach the goal.
To guarantee optimality (finding the shortest path), the heuristic function $h(n)$ must be:
1.  **Admissible:** It never overestimates the actual cost to reach the goal.
2.  **Consistent (or Monotonic):** For every node $n$ and every successor $n'$ of $n$ generated by an action $a$ with cost $c(n, a, n')$, the estimated cost of reaching the goal from $n$ is no greater than the step cost of getting to $n'$ plus the estimated cost of reaching the goal from $n'$: $h(n) \leq c(n, a, n') + h(n')$.

## 4. Pseudo Code
```text
function A_Star(start, goal, h)
    openSet := {start}
    cameFrom := empty map
    
    gScore := map with default value of Infinity
    gScore[start] := 0
    
    fScore := map with default value of Infinity
    fScore[start] := h(start)
    
    while openSet is not empty
        current := node in openSet having the lowest fScore[] value
        if current = goal
            return reconstruct_path(cameFrom, current)
            
        openSet.remove(current)
        for each neighbor of current
            tentative_gScore := gScore[current] + d(current, neighbor)
            if tentative_gScore < gScore[neighbor]
                cameFrom[neighbor] := current
                gScore[neighbor] := tentative_gScore
                fScore[neighbor] := gScore[neighbor] + h(neighbor)
                if neighbor not in openSet
                    openSet.add(neighbor)
                    
    return failure

function reconstruct_path(cameFrom, current)
    total_path := {current}
    while current in cameFrom.Keys
        current := cameFrom[current]
        total_path.prepend(current)
    return total_path
```

## 5. Parameters Selections
The choice of the heuristic function $h(n)$ is the most critical parameter:
*   **Manhattan Distance:** Suitable for grids where movement is restricted to 4 directions (up, down, left, right).
*   **Euclidean Distance:** Suitable for movement in any direction.
*   **Chebyshev Distance:** Suitable for grids with 8-way movement (including diagonals).
*   **Weighting:** $f(n) = g(n) + \epsilon \cdot h(n)$. If $\epsilon > 1$, the search is faster but potentially sub-optimal (Weighted A*).

## 6. Complexity
*   **Time Complexity:** $O(b^d)$ in the worst case, where $b$ is the branching factor and $d$ is the depth of the shortest path. However, with a good heuristic, it is much more efficient.
*   **Space Complexity:** $O(b^d)$ as it keeps all generated nodes in memory (Open and Closed lists).

## 7. Usage
*   Video games for character pathfinding.
*   Robotics for autonomous navigation.
*   Map applications (like Google Maps) for routing.
*   Natural Language Processing (parsing).
